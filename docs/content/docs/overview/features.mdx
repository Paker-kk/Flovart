Flovart 是本地优先的 AI 创作系统，产品由 Workflow、Table 与 Agent 三个职责清晰的工作区组成。

## 创作工作区

| 工作区 | 职责 | 当前状态 |
| --- | --- | --- |
| **Workflow** | 编排提示词、参考素材、生成模型、节点依赖、任务状态与结果；支持图片和视频生成链路。 | 已有可用基础，持续收敛交互与 Runtime 契约。 |
| **Table** | 组织 Agent 故事版和媒体预处理节点，把源媒体加工为可复用参考素材。 | 正式入口已接入；当前仍是占位界面，节点工作台待实现。 |
| **Agent** | 作为制作组控制面，组织 Director Binding、执行状态、审批、回执、上下文与产物。 | 目标架构已完成设计；现有“内置主 Agent”实现仍待迁移，不在本页宣称完成。 |

旧 Canvas / Art 工作区已经删除，不再作为第四套创作系统恢复。

## Workflow

- 使用图片、文本、视频、音频和配置节点组织生成链路。
- 通过 PromptBar 选择产品模型、生成模式、参数和参考素材。
- 支持节点连线、项目切换、本地媒体拖入、生成状态、停止与结果节点。
- 通过本地素材库复用角色、场景、道具和生成产物。
- 当前 CLI 注册表提供 Workflow 项目、节点、连线、视口、运行和停止命令。
- AI 原生 Workflow 的目标记录面由画布当前状态与语义 ChangeSet 时间线组成；聊天负责意图与解释，不作为唯一操作历史。该能力仍列在待办，不能误写为当前已完成。

## Table

Table 不是电子表格，也不是旧 Canvas 的改名。它计划提供两组渐进披露的节点能力：

- **Agent 故事版**：Brief、段落、场景、镜头和分镜卡片，支持 Agent Skill 生成、拆解与修订故事板。
- **媒体预处理**：图片或视频输入、人物抠图、深度图与深度视频、边缘/线稿/法线/姿态提取、风格化与故障滤镜，以及服装修改和全能参考前的素材准备。
- **产物交接**：处理结果保留来源关系，可保存到素材库并作为 Workflow 的参考输入。

Workflow 与 Table 按复杂度分工：Workflow 可以保留直接服务生成链的单步、局部操作；批量、多步骤、多输入/多输出、时间轴精修与可复用处理链进入 Table。两边可以复用媒体操作 Schema 与执行器，但不共享图节点或历史。

单步操作升级为复杂处理时采用显式 Table Promotion：Table 获得该处理链的编辑权威，Workflow 只引用明确发布回来的 Artifact；Table 内部试验不会双向实时覆盖 Workflow。

Table 主体尚未完成；在对应节点、持久化与导出链路落地前，不应把上述计划能力描述为已可用。当前 CLI 也没有 Table 命令。

## Agent

Agent 不是 Workflow 右侧聊天抽屉、外部 Harness 的聊天镜像，也不是另一张生成节点图。目标形态是制作现场的空间控制面：用可摆放面板展示 Director Binding、Intent、状态、待审批项、Workspace Operator Receipt 与 Artifact；主对话、总体目标和跨任务调度始终留在独立运行的 External Coding Agent Harness。现有代码仍以“内置 Flovart 主 Agent + Codex 子任务”为主，迁移工作列在[后续待办](../progress/todo.mdx)。

产品只有两个 AI 角色：外部导演 Harness 与唯一内置 Workspace Operator。Production Crew 只是“Operator + 确定性 Dispatcher/Runtime Capability + Provider Worker”的集合名，不是第三个 Agent；专业评审即使调用模型也只是一项无状态 Review Tool。

## CLI 与外部 Agent

- External Coding Agent Harness 是导演台。Coding Agent Projections 的模型工具通过 Operation Skill 学会使用 Flovart，并统一经公开 CLI 调用类型化能力；目标公开边界不提供 Coding Agent MCP Server。当前旧 Managed/Codex 适配器中的内部 MCP transport 是待删除迁移实现，不属于正式接入方式。
- Codex 是当前 professional golden path；DeepSeek Harness 保留显式 native Plugin projection；CodeBuddy Code、Claude Code、OpenCode、Pi 通过 stable Skill + CLI contract 兼容。WorkBuddy 属于未来 mainstream、skill-mediated projection，不在当前 Director Binding 范围内。
- DeepSeek Harness 的目标深度体验是专用 Flovart Profile + Host/Client Plugin：Harness 保持主壳、主会话和默认导演权，左侧固定 Flovart Dock 打开中央完整 Workflow/Table/Agent Production Control，快速弹层处理审批/状态/Artifact，右侧 Agent Bridge 管理连接与单导演 Handoff，并保留独立窗口降级。Host 仍经 CLI 执行模型工具，Client 只为 UI、事件与恢复使用受限本地通道；该能力尚未通过真实安装与恢复验收，不能写成当前已交付。
- Flovart CLI 是确定性执行器；`command.list` 与 `command.schema` 是 bootstrap、兼容诊断和调试使用的机器注册表。正常外部 Agent 循环只使用 `status`、`workflow.inspect`、`workflow.selection.get`、`workflow.apply` 与 `workflow.node.run`。
- CLI 内部可以使用版本化本地协议连接 Runtime；外部模型不直接依赖该协议。只有受信 DeepSeek Client Plugin 能在短期配对和限权范围内消费 UI/事件子集。
- 当前自动化能力以 Workflow 为主。Harness 不得伪造 Canvas、Element 或 Table 命令，也不得绕过 CLI 拼接私有 HTTP 请求。
- Provider 凭据由用户配置，CLI 和 Agent 输出不得读取或泄露 API Key。

完整目标、协议边界与迁移放行条件见 [Agent 架构设计包](../../../design/agent/README.md)。

## 本地优先边界

- 当前工作区项目、素材与生成记录主要保存在浏览器本地，不承诺云同步。
- 当前 API Key 保存在浏览器本地，并由前端直接请求用户配置的模型服务。
- Flovart 不内置模型服务；用户需要自行确认输入素材与生成内容的版权和合规性。
