## First Run → First Safe Generation：首启到首次安全生成

- 首次打开没有 AI 服务时仍可进入并编辑正常 Canvas；只有执行生成时才显示“添加 AI 服务”入口，不再以 Provider 错误或禁用按钮阻塞首屏。
- OpenAI-compatible 首次配置默认只要求服务地址与 API Key；连接成功后自动读取 `/models` 并补齐缺失的产品模型路由。模型列表缺失时支持手动填写模型，连接失败统一显示可行动的中文提示。
- PromptBar、Workflow Graph、`@` Mention 与素材库引用经过同一 Canonical Input；图生图、图生视频会把引用真实送入 `/v1/images/edits` 或 `/v2/videos/generations`，不支持的 capability 在请求前明确失败。
- 外部生成进入明确的费用确认 Gate。未经真人确认，Agent 的 `workflow.node.run` 即使携带伪造的 `confirmed: true` 也不会提交 Provider 请求；确认后的重试使用同一幂等身份，避免重复提交。
- 本机已用真实 localhost HTTP Fake Provider 与可见 Chromium 完成首次图片生成、图生图、图生视频、401/429/错误地址/超时、视频刷新恢复和错误重试；录制器只保存脱敏 header 与请求摘要，不保存原始密钥或 multipart 内容。
- 生成中的视频任务先持久化 Provider task ID，再进入轮询；刷新后继续查询原任务，不创建第二个提交。生成结果能够回到当前 Workflow 节点并在画布显示。

## Agent Surface Simplification：Host Projection 与精简工具面

- 新增版本化 Host Registry，把 Agent Identity、IDE Host、Distribution Target、Runtime Surface 和 Director Runtime Binding 分开；`init --target` 负责安装投影，`director.*` 只接受能映射到已实现 Runtime Binding 的 Agent Identity。
- `host.list` 只做 PATH 可执行文件发现，不读取登录文件、OAuth 或 API Key；Agent Host picker 只保存后续任务偏好，不自动切换 Director 会话。
- 内置 Agent 模型工具固定为 `status`、`workflow.inspect`、`workflow.selection.get`、`workflow.apply`、`workflow.node.run`。`command.list` / `command.schema` 仍可用于 CLI bootstrap、discovery 和 debug，但不再进入模型工具集合。
- Codex 是当前 professional golden path；DeepSeek Harness 保留显式 native Plugin projection；CodeBuddy Code、Claude Code、OpenCode、Pi 通过 stable Skill + CLI contract 兼容。WorkBuddy 仅作为未来 mainstream、skill-mediated projection 候选，不加入 `director.bind`，不阻塞本轮验收。
- Settings 中 Runtime 凭证与浏览器 AI 服务保持不同安全边界：Runtime 路由只展示非敏感元数据，浏览器直连凭证继续渐进披露；PromptBar 使用“AI 服务/访问凭证”产品词汇。

## 引用模型收敛：连接唯一事实来源

## Workflow Graph 输入解析纵切

- 新增统一的 `WorkflowResourceReference` 与 `resolveWorkflowInputs`：生成节点的输入从当前 `nodes + connections` 解析，带上资源类型、来源节点、连接身份和 Artifact/本地存储/可传输地址信息；URL 不作为引用身份。
- 新增 Node Output Contract：图片、视频、音频、文本、配置等节点通过注册的 definition 声明 `WorkflowResource`；Runtime Artifact、素材库和本地媒体分别保留自己的 locator，不再由输入 resolver 猜资源类型。
- 新增 `resolveWorkflowResource` Executable Resource Resolver：把声明 locator 解析为直连 URL、临时 Blob URL、Runtime Artifact 或内联文本；生成入口复用同一媒体 hydrate seam，并继续兼容现有旧字段投影。
- 现有 Workflow 生成入口和 `getUpstreamData` 共用这条解析路径。已连接的图片、视频、音频即使没有 PromptBar `@` 记录，也会进入候选输入；`@` 与 Seedance slot 仍可在同一连线边界内缩小范围和控制顺序。
- 空的已连接媒体不会被解析器静默丢弃，而会保留为不可用资源，让后续媒体解析返回具体缺失错误。
- 本纵切没有改写 Asset Picker、Mention 持久化模型或 Port 角色；它们仍需后续在同一 `ResourceReference → InputResolver` 契约上接入。

待用户确认：

1. 在 Workflow 中只把图片节点连接到图生视频/图生图节点，不输入 `@`，生成前后是否都能识别同一张图片。
2. 删除连接后重新生成，Provider payload 是否不再携带该媒体；重新生成上游后，下游是否读取当前 Artifact 而不是旧 URL。
3. 图片节点只有预览但没有可执行 Artifact 时，错误是否能明确指出来源节点，而不是只显示“需要上传图片”。

## Workflow Input Convergence（Phase B）

- Graph、Prompt `@` Mention 与 Asset 引用现在统一进入 `GenerationReference[]`，再由 `resolveWorkflowInputs` 生成唯一的 `ResolvedNodeInputs`；同一资源通过不同入口引用时会去重，并保留角色、顺序、来源和诊断。
- `buildCanonicalGenerationInput` 根据节点模式和已解析引用确定 capability 与 Provider 无关的 canonical 参数；`image-to-video`、`image-edit`、`text-to-video` 等模式不再由 Provider 或 PromptBar 重新推导。
- `mentionedNodeIds`、`referenceNodeIds` 与 `imageReferenceOrder` 已删除：引用顺序 = connections 数组顺序（新增 `reorder_connections` document op），选择 = 提示词文本 `@`；`seedanceReferences` 仍在 resolver 内作为 config 级 legacy 输入转换；Canonical Input 之后只由统一的引用物化适配层生成 Provider 参考数组。
- 生成入口接收轻量 Asset 索引，真实文件仍由 Executable Resource Resolver 按 locator hydrate；`artifactRef`、本地存储和 Asset locator 不会被转换成另一套引用身份。
- 已增加 Graph + Mention + Asset、重复引用、artifactRef-only、空媒体、角色冲突及 legacy 顺序/Seedance 映射测试；本阶段不改 PromptBar UI、Provider capability、DSH、Agent Workspace 或 Workflow SoT。

待用户确认：

1. 同一图片同时通过 Graph 连接和 `@` Mention 引用时，生成请求是否只携带一份媒体，并保留预期的 role/order。
2. Graph、Mention、Asset 三种入口指向同一资源时，节点预览、Canonical Input 和最终 Provider payload 是否一致。
3. 角色冲突、空媒体和仅有 `artifactRef` 的节点是否都能显示明确诊断，且不会静默降级为文生图/文生视频。

## Provider Capability / Adapter（Phase C）

- 新增独立的 `ProviderGenerationAdapter`：它只接收 `CanonicalGenerationInput`，按当前产品模型、Provider 和 route 声明可用 capability、参考媒体类型、角色及数量上限。
- Workflow 生成链现在先完成 Canonical Input，再经过一次 Provider capability validation 和一次 wire request serialization；Provider/Gateway 不再从 Canvas nodes、connections 或 metadata 重新组装引用。
- Canonical path 会把实际 route ID、生成模式和已 materialize 的参考媒体传入 Gateway；如果 route 不支持 capability、参考类型、角色或数量，会在 HTTP 请求前明确失败，不静默丢引用或降级成文生视频。
- 增加了 Provider seam、Gateway 拦截和最终 OpenAI `/images/edits` multipart body 测试；现有 RunningHub/Veo/Keling 的真实 request body 测试继续覆盖视频序列化路径。本阶段不改 PromptBar UI、DSH、Agent Workspace、Workflow SoT 或 Canvas mutation。

待用户确认：

1. 同一 Workflow 节点在图生图和图生视频场景下，Resolved Inputs、Provider wire request 与最终 HTTP body 是否保持一一对应。
2. 选择不支持当前 capability、参考角色或参考数量的 route 时，是否在发送请求前显示明确错误，且不会悄悄改成其它生成模式。
3. Runtime managed 的 `artifactRef-only` 图片是否仍能沿用同一 Canonical Input，并只在 Runtime wire mapping 阶段转换为 `sourceImageIds`。

## WorkflowExecutor 收敛（Phase D）

- UI、Browser Agent、CLI Workspace Adapter 与 Runtime/operator route 现在都进入同一个 `WorkflowExecutor.runNode()`；Dispatcher 不再持有第二套 `runNode/stopNode` 引用组装路径。
- `WorkflowRunCommand` 统一携带 `projectId`、`nodeId` 和可选 `expectedRevision`；每次执行生成 `runId`，统一传递 `surface`、`correlationId`，surface 不参与输入解析、capability 或 Provider mapping。
- Dispatcher 统一消费 Executor 的结构化结果和错误 code；CLI 的 `workflow.node.run/stop` 不再访问已删除的文件队列，只通过 loopback Workspace Adapter 转发到浏览器 Workflow Authority。
- 生成链新增 canonical observer，执行器可追踪同一次运行产生的 `CanonicalGenerationInput`；专项测试覆盖 UI、Browser Agent、CLI、Runtime 四种 surface 的 canonical JSON 等价性。
- 本阶段没有修改 PromptBar、DSH、Workflow SoT、Agent Workspace 或 Canvas `applyOps`；Phase C 登记的 DSH baseline failure 保持不变。

待用户确认：

1. UI、Browser Agent、CLI 与 Runtime/operator 对同一节点运行时，是否都显示同一 `runId`、错误语义和节点状态。
2. CLI 通过已连接 Workspace Adapter 运行/停止节点时，是否确实进入当前浏览器 Workflow，而不是回落到本地文件状态。
3. 提交 `expectedRevision` 过期时，所有入口是否都得到 `REVISION_CONFLICT`，且不会启动 Provider 请求。

## Browser Workflow Contract 与 Local Agent binding（Phase F0）

- Local Agent Session 不再在没有浏览器连接时自动启用 native workspace；native Workflow 只有经过明确的 `/workflow/native/register` 才能成为当前会话的执行 authority。
- `workflow.node.run/stop` 已在 canonical Registry 中标记为 `available`，但仍只由 Workspace Adapter 转发到浏览器 Workflow Executor，不会变成 Production Runtime 的第二套执行器或内置 Agent 的默认工具。
- CLI 仍只通过 loopback Workspace Adapter 调用浏览器，浏览器 Workflow 继续拥有节点、连线、Draft 与运行入口；本阶段没有新增私有 HTTP、shadow state 或 PromptBar Provider 分支。

## Workflow Mutation Contract（Phase G1）

- Workflow Document Mutation 统一通过 `WorkflowMutationEnvelope → applyWorkflowOps`，包含 `projectId`、`expectedRevision`、`mutationId`、`source` 与批量 `ops`；UI、CLI、Browser Agent 和 DSH Browser projection 共用同一 Draft Authority。
- Document Ops（节点/连线/布局）进入 Draft ChangeSet、revision 与 Undo/Redo；View Ops（selection、viewport、focus）不改变 Workflow revision；节点执行仍只经过 `WorkflowExecutor`。
- 新增 `workflow.apply` public contract；既有 granular `workflow.*` 继续保留为 compatibility adapter，只翻译为同一批 Document Ops，不再持有独立 mutation logic。Mutation Receipt 随项目持久化，重复载荷可重放，不同载荷明确拒绝。
- Browser-bound Agent 在没有浏览器绑定时返回 Workspace unavailable，不会隐式进入 NativeWorkflowStore；显式 Native/Headless workspace 仍保持独立边界。

待用户确认：

1. UI 与 CLI 对同一批节点/连线操作是否得到相同 Workflow state，并且 batch 只形成一个可撤销 ChangeSet。
2. 重复 `mutationId` 是否重放原 Receipt，旧 `expectedRevision` 是否返回 `REVISION_CONFLICT`，View Ops 是否不增加 revision。
3. `flovart start --open` 打开主页面后，浏览器是否自动完成 binding；当前默认 Windows URL handler 与本机实际 binding 已通过，仍需用户复查首次窗口体验。

## PromptBar Reference Contract（Phase G2）

- Workflow Node PromptBar 新增 provider-neutral `PromptIntent`：只表达目标节点、提示词、稳定引用身份和用户动作；现有 PromptBar 视觉、`@` 下拉、参考 chip、模型/参数交互保留。
- Graph、富文本 `@` mention、Asset 和 Runtime Artifact 现在统一进入 `GenerationReference[] → resolveWorkflowInputs → CanonicalGenerationInput`；同一资源通过 Graph 与 `@` 重复出现时只保留一份，并保留来源、顺序、角色和诊断。
- PromptIntent 的 mentions 只从富文本文档与 Operation inputBindings 派生，不再读取 metadata 引用数组；`first_frame`、`last_frame`、`reference`、`character` 角色已从 intent/resolver 验证到 Provider wire serializer。Provider 不支持某种引用时仍在请求前明确失败，不会静默退化。
- 产品模型、Provider route、capability、参数限制和费用展示计算已抽到 PromptBar policy service；组件不再直接导入 Provider Catalog/Gateway/wire serializer 或读取密钥内容。

待用户确认：

1. 在同一 Workflow 节点分别用 Graph、`@`、素材库和 Runtime Artifact 引用生成图像/视频，确认最终 Provider 请求只携带一份媒体且角色/顺序正确。
2. 在 PromptBar 中编辑提示词、添加/移除/拖动引用、切换图生图/图生视频/首尾帧/全能参考后，确认当前 UI 交互不变，生成前的引用仍准确反映最新意图。
3. 使用不支持所选引用类型、角色或数量的 Provider route，确认发送请求前显示具体错误，不会退化成无引用生成。

## Provider Extension Contract（Phase G4）

- 正式 Provider 继续使用 canonical capability/serialization seam；新增 `ProviderGenerationExtensionRegistry` 管理 User Script Provider，未绑定用户线路时仍回到正式 adapter，两个入口不共享 Canvas 读取旁路。
- User Script 第一版使用受限 JSON mapping DSL：request、response、poll、cancel 都是固定数据映射，不执行任意 JavaScript，不使用 `eval`/`new Function`，也不开放文件系统、React、localforage、任意网络或原始凭据。
- User Script 只能看到脱敏的 `CanonicalGenerationInput` manifest 和已物化引用；凭据只在宿主构造最终 HTTP header 时读取。endpoint 仅允许 HTTPS 公网地址，媒体输出仅允许 HTTPS 或 data URL，并限制 path 留在同一 endpoint。
- `executeUnifiedIgnition` 已支持通过 `UserApiKey.extraConfig.providerScriptId` 进入 User Script adapter；图片 immediate response、视频 task/poll/cancel 和 Graph reference → canonical → 实际 wire body 都有专项测试。
