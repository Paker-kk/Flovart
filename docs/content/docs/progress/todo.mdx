## Table：Agent 故事版与媒体预处理工作台

Table 是 Workflow 之外的第二个正式创作工作区，不是电子表格，也不是旧 Canvas / Art 的改名。当前入口已经接入，但主体仍为占位界面。

### 信息架构与渐进披露

- **统一图 + 焦点面板**：⬜ 故事卡、媒体和处理节点共用一张项目图；首层只展示「故事版」与「媒体预处理」两类任务，选中节点后再披露紧凑参数，复杂抠图或逐帧视频处理进入焦点编辑。
- **Agent 故事版**：⬜ 支持 Brief、段落、场景、镜头和分镜卡片节点；Agent Skill 可生成、拆解、排序、修订和解释故事板。
- **媒体预处理**：⬜ 支持源图片、源视频、处理节点和产物节点；默认流程是“选媒体 → 选处理 → 调整关键参数 → 预览 → 保存产物”。
- **紧凑扁平 UI**：⬜ 降低边框、阴影、胶囊和常驻面板数量；工具属性靠近当前节点，批量与高级参数按需展开。
- **弹性反馈**：⬜ 拖放、连线、展开、任务启动、成功回填和失败恢复使用 `motion` spring；动效只解释状态变化，不持续占用注意力。

### 节点与数据模型

- **Table 项目状态**：⬜ 定义 Table Project、Table Node、Connection、Viewport、Selection 与 History；业务数据使用 `localforage` 持久化。
- **节点图底座**：⬜ 在统一图前提下比较复用现有 Workflow 图层与引入 React Flow 的成本，确认后只保留一套 Table 渲染与交互底座，不再增加内部子画布。
- **故事版节点**：⬜ 实现 Brief、场景、镜头、分镜卡、参考素材和备注节点；支持排序、分组、批量选择与 Agent 建议。
- **预处理节点**：⬜ 实现媒体输入、处理操作、预览和产物节点；参数和运行状态归节点所有，不依赖全局弹窗堆叠。
- **产物来源关系**：⬜ 每个预处理产物保存源 Artifact、处理节点、参数摘要和创建时间，可进入素材库并作为 Workflow 参考输入。
- **撤销与恢复**：⬜ 图操作走轻量 History；长时媒体任务使用持久 `taskId`、取消、失败重试和结果恢复，不把二进制塞进撤销栈。

### 媒体预处理能力

- **人物与主体抠图**：⬜ 自动抠图、边缘修正、透明背景预览与导出；保留手动修正入口。
- **深度图与深度视频**：⬜ 图片深度估计；视频逐帧解码、批处理、进度、取消和重新编码，避免阻塞主线程。
- **结构参考提取**：⬜ 边缘、线稿、法线和姿态图提取，产物可直接作为后续生成参考。
- **风格化与故障滤镜**：⬜ 复古 DV、VHS、胶片、RGB 分离、扫描线、噪点和撕裂等可调预设，支持原图/结果对比。
- **服装修改准备**：⬜ 通过人物分离、区域遮罩、身份参考与服装参考组织，为后续 AI 编辑提供结构化输入；AI 生成本身仍由已验证 Provider Route 执行。
- **全能参考准备**：⬜ 把人物、场景、道具、动作和风格素材整理为带角色语义的参考集合，再交给 Workflow 的多模态生成节点。
- **视频处理管线**：⬜ 明确 WebCodecs / ffmpeg.wasm / Worker 的职责和降级边界；大文件必须支持进度、取消、内存上限和失败恢复。

### Agent 与 Workflow 互通

- **Table Agent Skill**：⬜ 复用现有 Agent 对话和 Tool Calling 基础，定义只操作 Table 项目与节点的类型化工具；不得复活 Canvas / Element 命令。
- **Workflow → Table**：⬜ 从 Workflow 选中图片或视频，创建带来源关系的 Table 输入节点，而不是复制无来源临时文件。
- **Table → Workflow**：⬜ 将选中产物保存到素材库，并一键创建或更新 Workflow 参考节点。
- **Canonical Command Registry**：⬜ Table 自动化能力只有在命令 Schema、实现与测试同时落地后才能写入 Skill；当前 CLI 不提供 Table 命令。

## Workflow 交互与能力收口

- **删除 Config 节点**：⬜ 单独评估现有模型/参数入口后移除冗余 Config 节点，避免先删入口再补交互。
- **Scene Prediction**：⬜ 基于首尾帧能力实现向前或向后续写镜头，并明确抽帧产物与新视频节点的来源关系。
- **音频生成**：⬜ 等 Provider 层提供已验证音频生成能力后启用；当前只保留音频上传、播放、引用和配置元数据。
- **布局规范统一**：⬜ 顶栏、侧栏、底部 Dock、外边距、圆角、阴影和主题 token 统一；清理 Workflow 硬编码间距和重复右侧面板实现。

## 制作 Runtime

- **统一 Runtime dispatch**：⬜ Runtime 查询、Task 查询/取消、Event 续读、`runtime.test.delay`、RunningHub GPT Image 2、Grok Imagine Video 1.5 低价路线和 Veo 3.1 Lite 已由唯一 Desktop Runtime 执行；继续迁入其他已验证 Provider Route，迁完后删除双轨执行面。
- **跨入口本地数据桥接**：⬜ Web 站点、Tauri WebView 与 Edge 扩展的 IndexedDB 默认按 origin 隔离；通过受限 Desktop Runtime API 共享 Workflow / 素材 / 历史等业务数据，API Key 只允许本地鉴权后调用，不向扩展返回明文。
- **Provider Task 完整语义**：⬜ 首条 RunningHub Route 已保存外部 job ID、轮询事件和 Artifact；继续补齐 ProviderAttempt、提交不确定态、真实百分比进度、失败分类与远端取消确认。
- **原子能力面**：⬜ 补齐 Provider Job、Artifact、Node、Render 与 Verify 的封闭类型 Atomic Runtime Command；Production Intent Command 由 Runtime 展开为 ProductionRun 与 StageRun。
- **Provider-neutral 能力**：⬜ Agent、CLI、MCP 与 WebUI 只请求产品能力，Provider Adapter 独占路由 payload、凭据和提交生命周期。

## Flovart Agent V1

- **类型化制作工具**：⬜ 为 PI Kernel 注册项目/素材/Runtime 查询、方案修订提案、Production Intent 与 Specialist Capability；不开放 Shell、任意文件和任意网络工具。
- **流式工具调用**：⬜ 在 Runtime `agent-text` 归一化协议中补齐 tool-call delta、结构化错误、断流重试和超时分类，并验证多轮 Tool Result 回灌。
- **主对话与探索分支**：⬜ 保留一条可恢复主对话；探索分支未提升前不得创建正式 Spec Revision 或 Mandate。
- **Production Plan Card**：⬜ 把目标产物、可选 Production Skill、Route Plan、预算和审片点投影为一张制作方案卡；“确认并开始”原子创建 Mandate 和 Run，普通聊天文本不得授权付费。
- **固定 Node Runtime**：⬜ 正式 Desktop 安装包捆绑满足 PI 要求的 Node `>=22.19.0`，Release Manifest 锁定 Node、PI、Agent 协议和 Session Schema；源码开发模式才允许使用合规系统 Node。
- **Managed Agent 生命周期**：⬜ Desktop 正常退出时必须同步终止其托管的 Managed Agent 子进程；实机验收发现源码开发模式关闭窗口后 Node 子进程仍会存活。
- **Agent 空间默认布局**：⬜ 新增 Codex 子任务时按主面板边界计算空位，避免默认位置大面积遮挡 `Flovart Agent`；仍需保留用户拖动后的空间布局。

## ProductionRun 与 Production Skill 生态

- **Production Skill Manifest**：🟨 已用 `community.vox-director` 内置 VOX Skill 示例落地版本、ProductionSpec 扩展 Schema、Runtime Capability、人工 Gate、兼容版本、来源与权限声明，并由 Skill 台读取同一真实包；继续补第三方包导入、签名、锁定快照、发布、撤销与预算策略。Production Skill 不得读取 API Key 或直接构造 Provider HTTP 请求。
- **制作领域模型**：⬜ 建立 `ProductionRun → Shot → Take → Artifact → Delivery`，将当前多个独立生成任务和外部合成脚本收进一条可恢复、可审计的制作图。
- **报价与批准状态机**：⬜ 将 `production.quote`、预算策略/用户批准与 `submit` 分开，支持单镜头和整片费用上限；价格预览与最终账单分别记录。
- **一等后期命令**：⬜ 注册旁白、字幕、混音、合成、响度和交付验证命令，使 Coding Agent 不再依赖评测目录的临时脚本。
- **图生视频一致性流程**：⬜ 先做 style bake-off、角色参考和静态关键帧，再以 image-to-video 生成镜头；把跨镜头角色、调色和品牌污染检查设为 Gate。
- **第三方 Skill 安全**：⬜ 增加签名、网络/Provider/文件权限、Secret 隔离、费用配额与审计日志，之后再开放 Production Skill UGC 安装与发布。
- **Research Adapter 正式来源**：⬜ 为 X 接入经过认证、可审计且遵守来源条款的正式适配器，并补限流、游标、去重和来源级健康度；不得用搜索摘要冒充 X 原帖。Reddit RSS 已完成 tracer-bullet，但仍需加入票数/评论数的正式元数据来源。
- **TUI 制作控制台 V2**：⬜ 在保持 CLI 为唯一命令入口的前提下，增加 Task drill-down、价格批准、Artifact 预览、Agent token stream 和失败镜头重做；TUI 不保存第三份 Runtime/Workflow 状态。
- **只读 Workflow Projection**：🟨 `production.dry-run` 已持久编译 ProductionRun/StageRun DAG，`workflow.projection.get` 与 Desktop 轮询 Adapter 已把计划节点自动投到真实 Workflow，并保留用户布局；继续补 `workflow.projection.updated` 事件和 Runtime Artifact 到对应 Shot/Take 节点的自动挂载。
- **可编辑 Spec/Layout Revision**：⬜ 语义细修改走带 `parentRevisionId` 的 `production.spec.create-revision`，节点位置/视口只走 `workflow.layout.update`；实现 CAS 冲突、局部 Stage 失效、旧 Take 保留和单镜头重做。
- **删除双轨状态**：⬜ Projection 接管后删除 `shadow-runtime-state.json`、Vite file queue 和浏览器完整快照作为命令真相；WebUI Local Agent Bridge 改为 Production Runtime Adapter。

## Provider 账单与取消

- **任务级取消**：⬜ 只对官方明确提供取消接口的线路保存 `providerTaskId` 并调用取消能力；未确认成功前 UI 只能显示“停止等待”。
- **实际账单回填**：⬜ 有账单或用量接口时将本机预估更新为实际费用；无法查询时保留“费用未知”，不自动退款或假定零消耗。
